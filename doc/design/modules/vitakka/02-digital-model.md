# Vitakka (ဝိတက်) — digital model

**State:** researched design specification; this file does not certify implementation. Read [Myanmar explanation](01-buddhist-explanation.md) before this document and [implementation design](03-implementation.md) afterward. Actual delivery evidence belongs to [status](../../../delivery/status.md).

## Purpose and interpretation

Represent an explicit initial line of inquiry concerning the already attended object: which bounded question or hypothesis is being taken up now. This is a chosen software use of the concept, not a complete definition or a requirement that every consideration verbalize a question.

The source identifiers VI-S1 onward belong to document 01. The requirements below are original engineering choices informed by that research, not statements attributed to the Buddha. Source-layer and terminology limits in document 01 apply. No database field, model response or software timing establishes a literal mental factor.

## Behavioral requirements

### VI-01 — Object-bound question

An inquiry must reference the current object and concern. It cannot silently replace the object with an attractive unrelated topic.

### VI-02 — Sufficient specificity

Distinguish a concrete investigable question from a broad aspiration such as assist. Broad interests can supply a seed without pretending inquiry has already progressed.

### VI-03 — Hypothesis status

An explanatory possibility remains inferred; posing it does not establish evidence or a finding.

### VI-04 — Relevant omission

Routine replies and considerations that need no explicit question may omit the facet rather than receive generated filler.

### VI-05 — Deliberate new angle

Changing the inquiry angle records its relationship or detour/return condition under the retained concern.

## Cooperation and ownership

Manasikara supplies orientation; vitakka proposes an inquiry angle; vicara examines it; chanda supplies interests. Do not move scheduling or authorization into this facet.
