# Vedana (ဝေဒနာ) — digital model

**State:** researched design specification; this file does not certify implementation. Read [Myanmar explanation](01-buddhist-explanation.md) before this document and [implementation design](03-implementation.md) afterward. Actual delivery evidence belongs to [status](../../../delivery/status.md).

## Purpose and interpretation

Retain explicitly modeled valence concerning the current object while separating it from reactive tendency and selected action. It is application appraisal, not a claim of subjective experience, suffering or literal vedana.

The source identifiers VE-S1 onward belong to document 01. The requirements below are original engineering choices informed by that research, not statements attributed to the Buddha. Source-layer and terminology limits in document 01 apply. No database field, model response or software timing establishes a literal mental factor.

## Behavioral requirements

### VE-01 — Object-bound appraisal

Bind modeled tone to the actual decision/object and attributable cause. A provider-supplied tone remains a model proposal.

### VE-02 — Valence versus reaction

Store pleasant/unpleasant/neutral separately from approach, avoidance, clarification or restraint. Unpleasant criticism cannot justify hostile speech.

### VE-03 — Unknown and disabled modes

Undetermined is an engineering uncertainty state, not a fourth doctrinal feeling. Disabled appraisal retains evidence and controls without inventing feeling.

### VE-04 — No success mapping

Do not infer pleasant from success or unpleasant from failure. Receiving accurate criticism may be useful while a pleasing claim can be false.

### VE-05 — Temporal change

New feedback may warrant a changed appraisal; preserve prior versions and reasons without claiming a persistent human mood or bodily state.

## Cooperation and ownership

Phassa/object records ground the context; sanna interprets; vedana models valence; cetana coordinates direction; sikkha authorizes independently. Rich emotions need their own justified model and cannot be silently relabeled vedana.

## Acceptance scenarios

| ID     | Situation and required outcome                                      |
| ------ | ------------------------------------------------------------------- |
| VE-C01 | Useful criticism arrives: permit correction without hostile action. |
| VE-C02 | A flattering false claim arrives: pleasant wording is not evidence. |
| VE-C03 | A file read fails: record actual failure, not physical pain.        |
| VE-C04 | Appraisal disabled: no tone-based policy bypass or hidden reaction. |
| VE-C05 | Screen feedback changes a premise: create a new linked appraisal.   |
| VE-C06 | No cause is attributable: use undetermined with uncertainty.        |

Evaluate the resulting records, next action, correction lineage and visible outcome using different contexts and paraphrases. Schema validity, a fixed sentence or a Pali folder name is insufficient. Where this is a catalog/reference boundary, evaluate source provenance and classification correctness instead of pretending it is live cognition.
