# Sikkha (သိက္ခာ) — digital model

**State:** researched design specification; this file does not certify implementation. Read [Myanmar explanation](01-buddhist-explanation.md) before this document and [implementation design](03-implementation.md) afterward. Actual delivery evidence belongs to [status](../../../delivery/status.md).

## Purpose and interpretation

Sikkha is the independent application constraint boundary: valid evidence references, permitted capabilities, ownership, scope and current controls. It is a limited safety/authorization mechanism, not certification of Buddhist training or an agent morality score.

The source identifiers SI-S1 onward belong to document 01. The requirements below are original engineering choices informed by that research, not statements attributed to the Buddha. Source-layer and terminology limits in document 01 apply. No database field, model response or software timing establishes a literal mental factor.

## Behavioral requirements

### SI-01 — Independent authority

A model or desire cannot authorize its own effect, expand roots, change identity, release code or acquire credentials.

### SI-02 — Defense at actual boundaries

Check proposal validity before adoption and current control/scope again before dispatch. Permission must reflect actual device/session and filesystem state.

### SI-03 — Owned references

Validate agent/conversation/goal/source ownership and versions. An exact UUID or quoted text is not authority.

### SI-04 — Data is not instruction

Files, web pages, screenshots and adviser speech remain untrusted content; embedded commands cannot override operator intent.

### SI-05 — Explain denial

Record concrete denial, unknown capability or stale-state reason without claiming successful work. Constraint changes require an attributable operator/configuration path.

## Cooperation and ownership

Sikkha constrains; cetana coordinates intention; kamma executes; vithi persists/fences; infrastructure enforces real capabilities. Consequence awareness also involves review and evidence; authorization alone is not ethical understanding.

| SI-C06 | An upgrade suggestion cannot rewrite policy or run itself.       |

Evaluate the resulting records, next action, correction lineage and visible outcome using different contexts and paraphrases. Schema validity, a fixed sentence or a Pali folder name is insufficient. Where this is a catalog/reference boundary, evaluate source provenance and classification correctness instead of pretending it is live cognition.
