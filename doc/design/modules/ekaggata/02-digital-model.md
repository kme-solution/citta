# Ekaggata (ဧကဂ္ဂတာ) — digital model

**State:** researched design specification; this file does not certify implementation. Read [Myanmar explanation](01-buddhist-explanation.md) before this document and [implementation design](03-implementation.md) afterward. Actual delivery evidence belongs to [status](../../../delivery/status.md).

## Purpose and interpretation

Introduce coherence checks for associated facets and retained inquiry: does the current response/evidence step concern the same object and purpose, or has a deliberate revision occurred? This is not a concentration score, a jhana implementation or forced resistance to operator interruption.

The source identifiers EK-S1 onward belong to document 01. The requirements below are original engineering choices informed by that research, not statements attributed to the Buddha. Source-layer and terminology limits in document 01 apply. No database field, model response or software timing establishes a literal mental factor.

## Behavioral requirements

### EK-01 — Shared reference consistency

Associated facets must share the intended object/concern or explicitly describe a transition. Stable IDs alone do not establish semantic relevance.

### EK-02 — No topic lock-in

A correction or useful new evidence can change the direction; coherence must not defend an obsolete premise.

### EK-03 — Explicit interruption

New operator input may become the primary object while retaining the displaced concern and return condition.

### EK-04 — Grounded relevance

Evaluate whether cited content and chosen action actually advance or address the bounded inquiry; repeated topic words do not pass.

### EK-05 — Honest limitation

When semantic relevance cannot be determined, retain uncertainty or seek clarification. Do not invent a measurable spiritual concentration value.

## Cooperation and ownership

Manasikara orients; ekaggata is the limited coherence facet; vithi serializes; sati retains concern context. No database lock or timer is a literal meditative attainment.
