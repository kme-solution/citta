# Nama (နာမ) နှင့် configured profile — digital model

**State:** researched design specification; this file does not certify implementation. Read [Myanmar explanation](01-buddhist-explanation.md) before this document and [implementation design](03-implementation.md) afterward. Actual delivery evidence belongs to [status](../../../delivery/status.md).

## Purpose and interpretation

The existing nama namespace currently owns configured conventional identity, not the SN 12.2 definition of nama. Preserve the useful profile behavior and record the naming debt. Do not implement a second mind object merely to make the folder sound doctrinally correct.

The source identifiers NA-S1 onward belong to document 01. The requirements below are original engineering choices informed by that research, not statements attributed to the Buddha. Source-layer and terminology limits in document 01 apply. No database field, model response or software timing establishes a literal mental factor.

## Behavioral requirements

### NA-01 — Conventional identity

Treat configured name and background as the agent persona/profile, distinct from operator identity and from doctrinal nama.

### NA-02 — Unknown stays unknown

Blank optional fields remain unspecified; do not invent age, gender, biography or past experience.

### NA-03 — Versioned changes

Only the supported operator/configuration path changes identity. Conversation or self-generated desire cannot silently rename or rewrite background.

### NA-04 — Privacy

Only allowlisted nonsecret profile attributes enter prompts/public responses. Credentials and private environment content never enter the identity model.

### NA-05 — Explicit naming correction

Document a future conventional-profile owner and preserve public/environment compatibility. Do not delete user records to fix terminology.

## Cooperation and ownership

Pannatti owns conventional labels; nama in the doctrinal source is not a profile database. Vedana/sanna/cetana/phassa/manasikara retain their own software facets. Sati memory and operator identity stay separate from configured agent background.
