# Dvara (ဒွါရ) — digital model

**State:** researched design specification; this file does not certify implementation. Read [Myanmar explanation](01-buddhist-explanation.md) before this document and [implementation design](03-implementation.md) afterward. Actual delivery evidence belongs to [status](../../../delivery/status.md).

## Purpose and interpretation

Dvara owns admission of attributable input into the one agent runtime. Channel labels describe the actual software transport. The six-door catalog remains doctrinal reference and must not determine invented laptop senses.

The source identifiers DV-S1 onward belong to document 01. The requirements below are original engineering choices informed by that research, not statements attributed to the Buddha. Source-layer and terminology limits in document 01 apply. No database field, model response or software timing establishes a literal mental factor.

## Behavioral requirements

### DV-01 — Attributable ingress

Retain agent, source kind, source key, received time and actual content/media reference. Operator speech, ability feedback and internally generated cues cannot impersonate each other.

### DV-02 — Idempotent receipt

A repeated source key with the same request returns the original receipt; conflicting content or reply target is a conflict. Receipt does not mean an answer exists.

### DV-03 — Communication continuity

Validate reply targets and conversation ownership before admitting them. Communication contexts do not partition the individual into separate memories.

### DV-04 — Actual channel capability

Admit a screen only when real capture supplied it. Missing microphone, screen or input capability remains missing; six reference doors do not create devices.

### DV-05 — Controls and corrections

Record input during allowed receipt states without bypassing Pause/Stop dispatch rules. Corrections retain their target lineage and can invalidate pending proposals.

## Cooperation and ownership

Vaca interprets speech; phassa binds available content; manasikara orients to an object; sati retains records. Dvara admits input and must not choose intentions or execute effects.
